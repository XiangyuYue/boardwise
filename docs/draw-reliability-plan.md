依据：[DSH会话审计](../evidence/dsh-session-37f77c38-audit/README.md)、[P48修复结果](../evidence/v4-fullpage/HANDOFF.md)、现有draw/CLI实现。

## 1. 目标与边界

目标是让DSH在受支持的电路范围内，稳定交付真实符号、正确连通、符合阅读规范的原理图；无法完成时尽早指出具体缺口，保留可用产物。

- 沿P48已完成结果继续，不重画智能药箱、不重启P145，不做eprj2绘图开发。
- P48属于agent-adjusted/reference replay成果，不作为任意新电路automatic能力证明。GND已修，关闭重开仍未验证。
- 复用现有PresentationSpec、PageLayoutPlan、module_plan、ChangePlan、apply、readability、lint和move-block；不新建builder、router、旗位器、页锚、通用缓存服务或另一套质量评分器。
- eprj3事实读取、已有工程受控调整、新电路生成分别记能力和验收，不互相代替。
- 继续遵守岛内短网拉线、跨岛信号命名、电源地旗标、真实文字与逐岛视觉规则。

## 2. 先修的三批

三批是可独立验收的顺序，不是一轮同时改多个文件域。实际实施前各立任务书，先冻结混合工作树归属、备份、聚焦基线和因果负控。

### A. 校正任务和资产入口，阻止继续用错输入

现象：新smartbox工程被代理自行解释成旧547A药箱；当前资产索引仍指P145自动线；未校准符号进入后续落图尝试。

做法：

1. 同步现有handoff、draw-line、draw-assets路由，以P48的实际状态为先；旧547A仅标逻辑草图材料，P145标历史暂停，不删除旧证据。
2. 每次任务先固定目标工程/页、新设计还是重绘、MCU与功能要求、电路来源、使用的符号资产。明确需求直接沿用，只有会改变电气设计的歧义才询问。
3. 使用已有来源/provenance和profile机制检查器件身份、物理脚号、引脚位置、姿态、旗标朝向与宿主所需文字。缺少真实几何的材料可用于逻辑讨论，不能进入已校准可落图状态；不能仅凭所有texts为空就断言所有元件无效，应检查实际需要显示的ATTR及已有文字测量证据。
4. 区分设计意图与电路实现：例如复位滤波、BOOT0下拉与实际网络不符，应在布局前曝光。不能把所有单脚网一概判错，也不能为过布局闸私改电路。
5. 记录实际插件版本、CLI路径/代码来源和相关资产指纹。现有doctor/version与元数据优先复用，排查运行版本不一致时给证据，不根据安装包名猜测。

验收：重放本次会话的错误入口，不能默默换设计、把547A宣称P48、用AI断言几何落图；正确的已测profile仍可用。任务类型和资产状态在首次长编译前可见。

首批范围以路由/资产说明为主，不附带编译算法改动。需要新增机器校验时另立窄批。

### B. 消除候选选择时的重复整页编译

现象：至少21次plan无成功；每次CLI plan先compile_page，再选candidate。最贵一次循环触发10轮整页编译。

已经存在的可复用路径：

- `cli.py` 的compile输出 `candN.page.json`（约14838行）。
- `draw apply <page.json>`（约15342行）消费已保存页，调用 `_draw_plan_from_page` / `module_plan` / `_draw_apply_flow`，不重新compile_page。
- 直接消费page仍可因module_plan失败而拒绝，不能把它当作绕过计划闸的方法。

做法：

1. 插件持有compile产物引用；选其它候选时直接读对应page，停止重复传三份源文件去触发完整plan重编译。
2. 复用现有 `_draw_plan_from_page` 做无写入的可执行计划预检；如果缺公开入口，只把这一入口以兼容方式暴露，不复制其逻辑、不另造缓存服务。
3. 在落图前保留源文件/几何匹配、分区、目标身份、当前页占用、位号池、基线和现有apply全部守卫。逐项核实profiles、引擎变更后的旧产物拒绝/复验行为，不能仅凭存在page文件就接受。
4. 源输入、页框、相关运行实现或现场障碍发生变化，按影响重新检查；确需重新排布才再编译。相同有效输入选N个候选不付N次整页编译成本。

验收：对与本次相同的候选选择流程计数，1次compile后检查4个候选，后续compile_page调用增量为0；plan/apply守卫仍运行。篡改源输入、profile或几何、占用目标区域应在写前检出。比较原链与产物链的计划/几何/网表，不以“更快返回”代替等价性。

计时：分别记compile、计划预检、bridge、写入、回读和渲染；先报测量基线，再承诺耗时目标。当前证据不足以承诺整张新电路几分钟必完成。

这是CLI/插件接缝改动，按shared-platform集成锁分批；不顺带迁移Rust或重写命令层。

### C. 让编译和计划消费同一组合法名称载体

已落C1/C2：3件2岛真实compile绿/plan红复现；在原reservation/carrier链输出实际导线，实际长度、名称行与最终计划几何一致；用原文字墙反馈处理`texts×segments`名称行冲突。没有新路由器或放宽规则。合成40单位4候选、60单位2候选通过；启用后编译较旧假绿更贵（初测约3.4/3.9秒对旧约0.38秒），计划消费约1–2毫秒，本批不作整页提速承诺。默认关闭不改几何但也保留旧失败。下一批先离线回放原失败输入，再分别分诊service路径与真实模块，不重画旧药箱。

现象：compile有候选，但plan重建40单位straight载体时与GND/I2C线冲突；reserve打开后又ESP_RXD压ESP_EN。

做法：

1. 使用本次I2C2_SDA拒绝报告及既有相关测试做最小复现，分别覆盖straight、auto、声明的stubMin、reserve开关和页打包后的结果。
2. 检查名称载体/标签框从局部模块到page再到module_plan是否保真。优先让现有生产链消费同一答案、同一尺；若现有合同不能承载，先列出缺失字段与调用者，再单独改合同。
3. 编译候选发布给代理前，复用B的同源计划预检。呈现上区分“几何候选”和“可执行计划”，保留旧ok语义，不把旧字段悄悄改成另一种承诺。
4. reserve后的新碰撞是另一个已定位缺口，只修相应carrier/label/route阶段；单岛通过后复验页组合。失败应指出具体标签、导线与阻挡关系。
5. 不把straight分支的40候选表推广为全部模式固定40；不以缩短桩、扩页框、隐藏文字或拆功能组来消除报错。

验收：选中候选的预览、计划与实际名称载体可逐项对应；静态几何冲突应在首次计划预检出现，不能等反复重编译后才发现。故意扰动载体/名称位置须先红，恢复后通过；不支持的例子明确拒绝，不制造新旁路。

## 3. 链路打通后的质量与能力扩展

### 真实符号和工程阅读质量

先验证已校准单模块，再组合多模块；每轮只处理一个有证据的缺口。P48作为参考质量锚，提取服务引脚关系、成对支路、旗标分组、可读文字等关系，不抄绝对坐标当新电路布局器。

质量验收分开记录：

- 电气输入与需求一致，落图后源网表逐脚对照，NC显式有依据。
- 生产可读性/lint检查通过；电源地用旗标、岛内短网直接连接、标题栏避开、文字不重叠。
- 最终原生符号渲染逐岛目检，包含同类对齐、贴服务脚、少拐弯、可见去向，并报告现有P44四条指标。离线矩形预览不替代这一项。
- 保存与关闭重开分开记；DRC开放项明确披露，绘图通过不代表可投板。

### automatic受阻时的有限调整

允许用户已授权范围内的agent-adjusted兜底，但只走现有计划、ATTR位姿、move-block/replay等受守卫接口；调整前后网表、电气分组及物理器件身份必须一致。需要改变网表、增加连接器、拆页等实质设计变化时，单独提出有证据的选择，不为绕算法静默修改。

现有 `agentadjusted.py` 只生成move-block proposed工单，目标空闲与网表证明由后续live planner完成；它不是通用离线几何编辑器。缺少某类调整操作时如实停在该能力缺口，不能再写一个自由逐脚拉线脚本。

同类问题第二次出现转成既有解释器的通用约束修复。用户体验目标是有可验证产物和确定的下一步，不把拒绝更快误算为绘图能力完成。

## 4. 插件执行和失败收敛

- DSH只封装现有核心能力，不在TypeScript重算电气、几何或质量结论。把产物→计划预检→守卫apply链暴露清楚，减少代理用shell自己拼流程的需要。
- 状态至少明确：逻辑草图、几何候选、可执行计划、已落图待验、绘图验收通过。状态绑定真实产物和实际检查结果，“画完了”必须有落图逐脚和原生视觉证据。
- 同一拒因两次无新证据就停止参数扫，转成一次窄诊断：指出决定代码/输入、阻挡对象和最小改动预测。新证据不足不再开第3轮。
- 一次只执行一个重计算任务，主代理负责当前流程，必要时一个独立审阅者；不把多子代理和后台长命令当作默认提速方法。
- 任务开始给出预算，耗尽后返回已生成的候选、首拒因、未做项与最小下一步。长阶段展示已知进度，不能在只有脚本排队或待审批时说“正在落图”。
- 延续会话内有效授权，材料变动/目标改变时按实际边界处理；不为可逆读操作反复询问，也不以性能为由取消写入身份/权限守卫。

## 5. 验收样本与发布顺序

| 样本 | 要证明什么 | 不能冒充什么 |
|---|---|---|
| P48修后捕获资料 | 校准符号、GND自然姿态、受控调整的质量与网表基准 | 任意新电路automatic成功、已重开验证 |
| 已验收CH340/CH343或当前真实单模块 | 既有正常消费者几何/连通/读法保持 | 新整页已通过 |
| 本次失败材料 | 错输入早披露、候选不重复编译、compile/plan分歧被检出 | 只会拒绝就是会画图 |
| 新设计样本：原超声波任务 | 在用户确认后的STM32F103、外部晶振、供电与显示要求上，从真实符号走完整闭环 | 用药箱旧三件套替代需求 |

新设计先做MCU最小系统/晶振、供电、超声波接口/电平、显示四类模块，再验证组合。供电要求中的Type-C与12V等关系须在已有意图合同中明确，不在几何阶段猜。每个新缺口单独成批；不以复现P48坐标作为“新设计成功”。

成功标准同时包括：完整落图成功、逐脚零差异、原生视觉合格、无无效重编译、没有无证据的长循环。先取得同机基线和分阶段计时，再设性能阈值；不能通过少验收、降阈值或换更宽夹具来满足。

日常按各批影响面跑聚焦测试、owner/layer与必要因果变异；实现与独立验收分开。集成/发布再按仓库要求做全量、connector、DSH、tsc/Rust及真机/打包后真实DSH使用验收，旧界面兼容检查不能省。原始失败样本继续留存。

## 6. 建议拍板的执行顺序

先A校正入口，再B复用产物，再C闭合名称载体合同；完成后才做新模块的有限能力扩展与DSH端到端验收。A/B/C通过前，不开新整页算法战、不发布“绘图已解决”的版本。

本草案不承诺工期。每批在开工前给出唯一缺口、文件域、完成条件、预算与停止线，完成后交真实读数，再决定下一批。CLI/shared、算法、插件和迁移分开，不打包成一次大重构。
