## 1. 现状证据（截至 2026-11-03，均为本仓库可核对的事实）

1. **仓库没有原生 CBB 实现**：`src/` 里没有任何 `block_symbol` 读点或写点，`review` /
   `draw` / `edit` 三条链都不认识 CBB。这是「没有」而不是「有缺陷」。
2. **`core/blocks.py` 的 `BlockSymbol` 不是宿主原生 CBB**：它是 008 生成器的**绘图模板域**
   ——block template 文件里的符号几何合同（块本地坐标、origin、ports），由 `generate`/
   `replay` 消费。它与宿主原生 `block_symbol` **同名不同物**，不得互相喂数据，也不得
   拿来当「CBB 已解析」的证据。
3. **宿主侧只有声明级线索**：`docs/api-surface-2026-09-20.md` 的 LIB_* 组里列了
   `lib_Cbb`（含 CRUD / search / `searchByProperties`），`docs/epru-format.md` 记
   `project2.json` 有 `cbb_project` 字段。**这些是声明与字段名，不是本机的行为实测**；
   哪一个是「库里的 CBB」、哪一个是「工程里的已接块」，目前都未验证。
4. **type 17 未证实**：`type 17` 是用户给的线索（疑为原生块在记录流里的类型号）。本机没有
   任何样本证实它，也没有反证。**在拿到样本、逐字节核对之前，文档与代码都不得把
   「type 17 = CBB」写成事实**（见 §3）。
5. **038P 的多 PCB 形状**：同一 `source`/`runner` 逐板审查已成立；`test V4` 两个**空 PCB**
   在线/离线 `boards`、`checksRun`、findings 一致（32 checks / 40 findings），但
   `review --view pcb` 多板仍拒绝（一模型一板）。多文件合流的守卫（038P1）也已落：
   `FOOTPRINT`/`DEVICE`/`SYMBOL` 同名库只有内容相同才允许合流、**分歧拒绝**、**重复 PCB
   拒绝**、无 uuid 板按文件名命名。但这些守卫只有**合成样本证据**，真实多板 + 各自携带
   同名库文档的工程**未实测**——CBB 不得假设这个形状已经通过。
6. **库投影的现状**：038M/038N 已让 `device-library-sample` / `footprint-library-sample`
   进差分 case book（工作树），CBB 没有任何对应 kind，也没有库侧冲突计数口径。
7. **规则侧现状**：没有块端口规则。所以「已接块端口在展开网表里缺席 → 被当真悬空误报」
   这一类**尚未被真实证据触发**，属于待证伪的假定，不是已记录的误报。

## 2. 范围 / 非目标

**范围内（按阶段推进）**

- 官方库搜索/身份/归档：CBB 在库侧的可寻址身份（name/uuid/分类）、搜索通路、归档读取。
- 受控个人库样件：在个人库里造/放一个最小块样件，符号构建并放置到目标页。
- 本地容器解析：`.eprj3` / `.epro2` 里已接块的记录识别与结构化读出。
- 写后回读：写入的块必须能用**真实 `block_symbol`** 回读（不是「回读成功」这四个字，
  也不是拿模板 JSON 自证）。
- 块端口规则：已接块端口在展开网表缺席时**不误报**，真悬空仍报，普通器件检查读数不变。

**非目标（本批及后续阶段都不做，除非另立任务书）**

- 不把 `core/blocks.py` 改造成宿主 CBB 的实现或反过来的适配层。
- 不在没有样本时按 type 号猜结构、不写「兼容 CBB」的结论。
- 不做 CBB 的绘制/自动生成（画一个新块），只做识别、放置、回读、规则口径。
- 不改 verdict、severity、exit code 合同，不为 CBB 单开一套报告 schema。
- 不碰真实工程（真机只 `test` / `test2`，按 R1–R3）。

## 3. type 17 待证实（口径钉）

- 现状：**未证实**。用户线索指出 type 17 可能是原生块记录；本机无样本、无差分。
- 需要的证据（缺一不可）：① 一份含至少一个已接块的真实容器；② 该容器里块的记录原文；
  ③ 与「普通器件 / 分页 / 库文档」记录的类型号逐条对照，能解释为什么不是别的类型；
  ④ 同一块在线 `doc.list` / 回读能对上同一身份。
- 证伪的处理：如果样本显示 type 号不是 17（或随版本变化），**按实测改口径**，在本文档
  §1 记一条「原线索被证伪」并保留原句，不悄悄抹掉；解析按实测字段，不按常量猜。
- 禁止：在任何文档、注释、测试名里把 type 17 写成已确认的事实；只能写「线索/待证实」。

## 4. 阶段（A → E，逐阶段开闸）

每阶段单独成批、单独验收，上一阶段没过不许开下一阶段。shared / connector / 规则 / 真机
**分批**，不同批混做。

### 阶段 A：离线只读（不开工直到有真实 CBB 样本）

- 目标：只读地认出「这是一个块」，说清它的身份（库引用、uuid、名）与端口集合。
- 允许：离线解析、只读探针、差分 reading；`evidence/038q/` 落原文片段与解读。
- 完成判据：同一容器 Python 侧读出的块身份/端口能与在线只读回读对上；读不出就明确报
  「不认识」，不猜、不静默降级成普通器件。
- 禁止：任何写动作、任何 `review` 结论变更。

### 阶段 B：只读动作 / 归档

- 目标：把块的库身份接进归档（库搜索/身份/归档通路），只读。
- 完成判据：库侧能按名字/身份找到该 CBB 并归档；找不到时如实报未找到（R3：找不到 ≠ 已清）。
- 禁止：写库、写工程、改 connector 行为面以外的东西。

### 阶段 C：受控写（个人库样件 + 页内放置）

- 目标：在**个人库**造一个最小样件，符号构建后放置到 `test`/`test2` 的指定页。
- 先读后写：写前必须先回读目标页身份（`doc.list` 焦点工程名与任务书逐字一致 + 页特征全项
  命中）；写后必须回读**真实 `block_symbol`**（含 uuid/端口），回读不到就报失败，
  不许用「已发送」「计划已应用」替代。
- 完成判据：写 → 回读 → 删除样件，三步都有证据；删除走回收站，不留残件。
- 禁止：写真实工程、写别人的库、把 `saved_unverified` 写成 verified。

### 阶段 D：块端口规则（误报修复 + 三条 negative control）

- 目标：已接块的端口在展开网表里**缺席**时不再当真悬空；同时不放过真悬空。
- 完成判据：§5 的三条 negative control 全绿，且普通器件读数逐字不变。
- 禁止：为消误报而放宽「悬空」定义到普通器件；禁止把一个规则类豁免写成全局静默。

### 阶段 E：真机验收

- 目标：`test`/`test2` 上做一次完整往返（放置 → 回读 → 审查 → 断连/删除）。
- 完成判据：真机证据目录 + 三条 negative control 在真机侧各跑一次；`incomplete/partial`
  如实写，不冒充板级通过。
- 禁止：在没有 R1 身份证据的情况下申报「删错/损坏」（R2：证据不足只报异常待裁）。

## 5. 三条硬 negative control（缺一条不许写「兼容 CBB」）

- **N1 已接块端口静默**：一个已接块的端口在展开网表里缺席时，**不得**产生悬空类 finding。
- **N2 真悬空仍报**：同一批里人为留一个真悬空脚（块外普通器件），**必须**仍报。
- **N3 普通器件读数不变**：不含任何 CBB 的对照工程，findings 条数与逐条内容**逐字不变**
  （与改动前基线对拍，不是「看起来一样」）。

三条都要有可重跑的测试或探针 + 证据落盘；只写「已验证」不算。
