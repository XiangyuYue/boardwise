# 545 · checkup 同目录并发互斥与重跑提示（审查线 shared 小批）

> 来源：2026-11-04 测试 T-E09 / T-E04。基线包含 544 的写盘异常修复，不得回退。
> 本批不改规则、模型、报告 schema、在线寻址、绘制算法，也不改其它命令的写盘合同。

## 合同

- 同一 `--out` 同时只允许一个 `checkup` 运行。后到者在读模型、拉 daemon 或写报告之前 exit 2，明确说明另一个审查正在使用该目录，无 traceback。
- 串行重跑同一 `--out` 继续允许；不得把既有“重跑保留人工分诊/摘要”的能力改成拒绝。
- 第二次串行运行若已有 `report.json`，正常输出必须明确：机器生成物会更新，人工内容按既有合并规则处理。不得笼统承诺所有人工文件永远不变。
- 正常返回和异常返回都必须释放锁。优先使用标准库 OS 文件锁，避免崩溃后遗留永久锁；不引入依赖。
- 不为消除竞争而给 `_cmd_checkup` 的上千行主体整体缩进；可用小包装器/装饰器保持 diff 可审。

## 允许文件域

- `src/boardwise/cli.py`：checkup 输出锁、生命周期与重跑提示，544 既有边界不得回退。
- 新增 `tests/test_545_checkup_output_lock.py`。
- 本文及最终必要的台账由主代理处理。

## 验证

- 至少：真实子进程持锁时第二个命令拒绝；子进程退出后锁可再次获得；异常返回释放；两次串行真实运行第二次有提示且无冲突；无效参数零锁产物。
- 先红后绿；至少两处独立变异被捕获，cp + SHA-256 恢复。
- 聚焦跑 545、544、checkup、owner、分诊/摘要邻域，不跑全量、不连真机。
- 日志放 `.tmp_545/`；pytest 用独立 `.tmp_pt_545`。
- 禁止 git 写、依赖安装、下级代理、任何 shell `rm` / `unlink` 清理。不要改其它现存文件。
