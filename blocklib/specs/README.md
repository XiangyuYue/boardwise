# `blocklib/specs` — the shipped spec library

23 files, four kinds, and the pairing between them is **by name**:

| kind | count | filename pattern |
|---|---|---|
| board spec (`boardwise-board-spec`, blocks + connections) | 2 | `ams1117_smoke.json`, `ch340g_usb_uart.json` |
| circuit spec (`boardwise-circuit-spec`) | 6 | `<name>.circuit.json` |
| symbol library (`SymbolProfile` book) | 6 | `<name>.library.json` |
| presentation (`PresentationSpec`) | 9 | `<name>.presentation.json` |

A draw run needs three of them and they are **not interchangeable across
families**: `<name>.circuit.json` + `<name>.presentation.json` + *that spec's own*
`<name>.library.json` as `--profiles`. The global `blocklib/symbols/profiles.json`
is a different book and makes these specs answer `[facts-missing] … have no
SymbolProfile with pins` — a correct refusal, but the wrong pairing, and the CLI
says so (`try: first check whether --profiles is the spec's own library`).

Two cross pairs are deliberate, not typos: `ch343_uart_534a.circuit.json` is
compiled against both `ch343_uart_534a.presentation.json` and
`ch343_uart_v4.presentation.json` / `ch343_uart_v4.library.json` (534 and 534a
are two readings of the same board, and both are shipped).

## The two presentations that have no in-library circuit (625A-08)

`ch340c_usb_serial.presentation.json` and `sy8089_buck_3v3.presentation.json` load
and compile, but **no `<name>.circuit.json` for them is shipped here**. Their
circuits were generated by the 038q11 / 038q12 offline pilots and live outside the
library; those files are `"draft": true` and carry `ai_asserted` declarations (for
example an NC on a pin nobody measured), so they are **not** library inputs and
were deliberately not copied in. Reproducing either page therefore needs a
reviewed circuit of your own next to it.

601 batches and later should read this as: *two of the nine presentations cannot
be re-run from this directory alone*. That is a known, stated gap — not a missing
file someone forgot to commit.
